# 월별 통합 수강관리 / 기본 OFF

## 승인된 범위

수강일 대신 연월로 관리합니다. 리치온은 1/3/12개월 이용권, 프리리치온은 기수별 고정 2개월입니다. 연장은 확정된 개월을 누적하고 개별 구매 이력은 보존합니다. 자동결제는 없으며 실제 할인율/판매가는 임의로 설정하지 않습니다.

기준은 `feat/backend-portal-readonly` / `d9fa315e7cf0f5e1f52d026cf2b92a74dd06c93f` (PR #6)입니다. 이번 PR은 앞서 제공한 월별 수강관리 초안을 기존 포털에 연결합니다. 등록/수정, PG 결제, 영수증 발급, 알림, 로그인 제공자 연결, 실서비스 배포는 포함하지 않습니다.

## 구현 파일

- `monthly_store.py`: 월 연산 / 읽기 전용 통합 조회 / 과정별 인원 / 신청·연장 이력.
- `monthly_portal.py`: 관리자 접근 검사 / Origin+CSRF 보호 POST 검색 / 과정 선택 / 이력 조회 / 정적 화면.
- `portal_static/enrollments.html`, `.css`, `.js`: 반응형 통합표 / 17개 열 선택 / 복합 필터 / 상세 / 페이지 이동 / 오류·재시도.
- `migrations/004_monthly_enrollments.sql`, `monthly_migrate.py`: 명시 적용용 준비 스키마. 001~003 체크섬 선행 확인. 앱 시작 시 적용하지 않습니다.
- `tests/test_monthly_pure.py`, `test_monthly_api.py`, `test_monthly_postgres.py`: 월 계산과 인증/검색/SQL/집계 검증.
- `main.py`, Docker/ignore/CI: 기본 OFF로 연결하고 런타임 코드만 업로드 허용합니다. 신규 DDL·적용기·테스트는 런타임 이미지에서 제외합니다.

## 운영 규칙과 화면 의미

1. `2026-10` 시작 3개월은 2026년 10~12월, 확정 1개월 연장은 2027년 1월까지입니다. 프리리치온 2개월은 10~11월입니다.
2. 한 수강생+과정/기수는 한 줄입니다. 확정 인원은 내부 learner_id 기준으로 중복을 제거합니다. 이름/연락처가 같다고 사람·계정·과거 주문을 합치지 않습니다.
3. 요약은 화면의 조회 월과 현재 필터 기준입니다. 페이지 이동 전 전체 필터 결과를 집계합니다. 전체 중복 제외 인원과 과정별 수강 건수는 별도입니다.
4. 확정 대기 신청은 확정 수강월을 늘리지 않습니다. 복수 대기안의 범위는 가장 긴 안까지 포함하며, 확정 인원에는 포함하지 않습니다.
5. 기간·결제·영수증 필터는 동일 구매 이력 한 건에서 모두 일치해야 합니다. 표의 최근 신청 정보와 누적 결제 기록은 구분합니다.
6. `payment_state=recorded` / `receipt_state=recorded_issued`는 외부 증빙의 기록 모델입니다. 증빙 참조 문자열이 있어도 실제 PG 검증이나 영수증 발급을 의미하지 않습니다. 이번 PR에는 기록을 생성하는 공개 API가 없습니다.
7. 확인되지 않은 금액·회원가입일은 NULL/미확인으로 표시하며 0원 또는 임의 날짜로 바꾸지 않습니다. 연락처 원문은 목록에 반환하지 않습니다.
8. 같은 과정의 연속 이용 구조입니다. 공백 후 재가입, 일시정지, 과정 이동, 환불에 따른 수강권 조정은 후속 설계입니다. 기존 확정기간의 삭제·개수 변경으로 이후 이력을 당기는 동작은 차단합니다.
9. 열 선택은 현재 화면에서만 유지합니다. 영구 보기 저장, 열 순서 변경, 임의 데이터 필드 추가, 개인정보 내보내기는 포함하지 않습니다.

## 경로와 적용 경계

- `/portal/enrollments`
- POST `/portal/api/admin/enrollments/search`
- GET `/portal/api/admin/enrollments/options`
- GET `/portal/api/admin/enrollments/{enrollment_id}/terms`

`RICHON_MONTHLY_ENABLED=false`가 기본입니다. 사용하려면 기존 auth/portal 준비와 정확한 origin 설정, 승인된 DB 적용이 모두 필요합니다. POST 검색도 도메인 데이터는 읽기 전용이며 검색어를 URL 대신 본문으로 보냅니다. 기존 세션 last_seen 갱신은 유지합니다.

이 PR 자체로 실제 Neon, Cloud Run, IAM, 원본 홈페이지, index.html/apply.html을 변경하지 않습니다. 기존 포털 PR 위의 후속 PR이며 병합·배포하지 않았습니다. 관리자 메뉴 연결 및 실제 로그인·도메인/쿠키·최소권한·감사/요청제한·개인정보 로깅 검증은 공개 전 작업입니다.

앞선 분리 미리보기에서 월 연산 30개와 가상 API 기반 UI 15개 시나리오를 확인했습니다. UI 가상 응답은 실제 SQL/세션/PG 검증을 대신하지 않습니다. 이번 업로드 후 기존 GitHub Actions에서 전체 백엔드/임시 PostgreSQL/Docker 및 기존 포털 UI 검사를 실행합니다. 실제 결과는 PR에 별도로 기록합니다. 실제 Neon 마이그레이션, 실제 OAuth·PG·고객 데이터 시험은 수행하지 않습니다.
