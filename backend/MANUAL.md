# 기존 수강생 수동 관리 / 정적 관리자 미리보기

## 범위와 실제 적용 상태

사용자가 승인한 관리자 테스트 페이지와 기존 수강생 수동 CRUD입니다.
기준은 `feat/backend-monthly-enrollments`의 PR #8입니다. 원본 홈페이지, Cloud Run, Neon DB,
IAM, Secret, 실제 회원 및 결제 데이터에는 적용하지 않습니다. 신규 PR은 병합하지 않습니다.

- `admin-test.html`: index-test처럼 정적으로 열 수 있는 단일 HTML. **가상 데이터만** 포함합니다.
  변경은 브라우저 탭 메모리에만 존재합니다. 새로고침하면 초기화되고 서버/DB/외부 전송이 없습니다.
  로그인 없이 볼 수 있지만 실제 관리자 인증을 통과한 것이 아닙니다. 실제 개인정보 입력 금지.
- `/portal/manual`: 실제 UI / 실제 관리자 세션 + Origin + CSRF 확인 후 API를 호출합니다.
- `/portal/enrollments`: 수동 등록한 내역도 같은 월별 구조에서 집계합니다.
- 관리자 메뉴에 월별 수강관리 / 수동 등록·수정 진입 링크를 추가합니다.

## 수동 CRUD의 의미

| 기능 | 처리 |
|---|---|
| 생성 | 신규 수강생 기록 + 과정별 신청 생성. 회원가입이나 PG 주문은 만들지 않음 |
| 조회 | 마스킹 목록 / 권한 확인 후 원문 상세. 원문 상세 조회 감사 이벤트 기록 |
| 수정 | 이름·닉네임·이메일·전화번호·기존 가입일 수정. 같은 수강생의 여러 과정에 공통 적용 |
| 신청 수정 | 미확정 수동 신청의 기간·금액·결제 증빙·영수증 기록·신청일 수정 / 명시적 수강 확정 |
| 연장 | 기존 확정 이력을 유지하고 새 1/3/12개월 신청을 추가. 미확정 신청이 있으면 먼저 처리 |
| 삭제 | **논리적 보관**. 수강 인원·통합표에서 제외, 이력 유지. 보관함에서 복원 |
| 과정 준비 | 기록용 과정·기수·시작월·1/3/12개월 또는 고정 2개월 정의. 판매 enabled=false |

확정된 기간/결제 이력을 덮어쓰거나 영구 삭제하는 것은 포함하지 않습니다.
그 정정에는 사유·전후 기록과 별도의 조정 규칙이 필요합니다. 실제 환불/영수증 취소/기간 차감은 없습니다.
기존 월별 DB의 확정 이력 보호 트리거는 변경하지 않습니다.

`original_joined_on`은 **기존 가입일 기록**이며 새 사이트 회원가입일을 날조하지 않습니다.
원 신청일과 기존 결제일은 운영자가 날짜로 입력하고 한국시간(+09:00) 날짜 기록으로 저장합니다.
수강 시작·종료는 계속 월 단위이며 영상 접근 만료 시각을 뜻하지 않습니다.

결제 상태 `recorded`와 영수증 `recorded_issued`는 **증빙을 확인했다는 수동 기록**입니다.
기록 금액·날짜·참조를 명시해야 하며 이 코드가 PG나 세무 발급 기관을 검증하거나 호출하지 않습니다.
`pending` 결제는 수강 확정할 수 없습니다. 기간별 실제 판매가/할인/PG 검증은 별도 기능입니다.

동명이인·같은 번호를 자동 병합하지 않습니다. 기존 수강생의 다른 과정 추가는 상세 화면에서
명시적으로 같은 learner_id를 재사용합니다. 로그인 회원으로 연결하는 권한은 제공하지 않습니다.
원문 개인정보와 결제 식별값은 정적 미리보기 / 테스트 소스 / 일반 로그에 넣지 않습니다.

## 동시성 / 권한

- 모든 쓰기와 상세 조회는 관리자 세션 + 정확한 Origin + 세션 결합 CSRF를 확인합니다.
- 저장 트랜잭션 안에서도 현재 관리자 역할/상태를 확인합니다.
- actor + request_id에 묶인 멱등 처리. 같은 요청 재시도는 기존 결과, 다른 본문은 409.
- 수강 등록 버전과 공유 수강생 버전으로 이전 화면의 덮어쓰기를 막습니다. 충돌 시 새로 조회합니다.
- 도메인 변경과 감사·중복 방지 이력을 같은 트랜잭션으로 커밋합니다. 커밋 실패 시 성공 반환 없음.
- 개인정보 상세 조회 자체도 감사 기록에 대상 ID·필드 목록만 남깁니다.
- 보관은 쓰기 플래그를 나중에 꺼도 유지됩니다. 월별 조회는 해당 보관 스키마가 있으면 항상 제외합니다.
- 신원 연결/역할 지정/실제 주문 수정/PG 결제 처리/기존 확정 기간 덮어쓰기 경로는 없습니다.

## 공개 전 조건

`RICHON_MANUAL_ENABLED=false` 기본값입니다. 실제 활성화에는 AUTH/PORTAL/MONTHLY도 활성화하고
001~005를 검토 후 적용해야 합니다. 실제 DB 적용은 실행하지 않았습니다. 앱 시작 시 DDL 없음.

현재 카카오·네이버 로그인은 앱 키만 추가하면 끝나는 상태가 **아닙니다**.
회원 식별/세션/로그아웃/권한 기반은 있지만 제공자 authorization code 교환, state/재사용 방지,
가입 동의, callback·도메인·브라우저 쿠키, 관리자 지정, 실제 로그인 검증이 남았습니다.
AUTH.md의 계약을 그대로 따릅니다. 이 PR에 가짜 로그인이나 관리자 권한 우회는 없습니다.

최소권한 DB 역할과 append-only 감사 권한, 원문 개인정보 접근·보관 정책, 요청 크기·빈도 제한,
민감정보 로그 차단, 실제 인증/브라우저/Neon 종단간 검증은 운영 활성화 전 작업입니다.

## 테스트

기존 backend-ci의 임시 loopback PostgreSQL만 사용합니다. 실제 Neon DSN은 금지됩니다.
`test_manual.py`는 검증·API 접근 경계, `test_manual_postgres.py`는 실제 SQL CRUD/중복·동시성/
버전 충돌/보관·복원/집계/커밋 실패를 확인합니다.
`preview/build_admin_preview.py`로 실제 UI에서 네트워크 없는 데모를 생성하고
`preview/check_admin_preview.py`로 가상 UI CRUD/모바일/문자열 렌더링을 별도로 검사합니다.
정적 미리보기 테스트 통과가 실제 OAuth/PG/운영 DB 검증을 뜻하지는 않습니다.
