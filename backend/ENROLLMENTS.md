# 통합 수강관리 조회 준비 v0.2

## 사용자 확정 규칙

- 수강 시작은 결제일/회원가입일이 아니라 **과정·기수별 수업 시작일**.
- 1/3/12개월은 30/90/365일 환산이 아닌 **달력 개월 수**.
- 기간이 끝나기 전 연장은 기존 시작일에 누적 개월 수를 더함. 과거 신청을 덮어쓰지 않음.
- 일시불 기간제. 자동결제/자동 연장 없음. 기간별 판매가로 장기 할인 가능. 실제 가격/할인율 미지정.

## 범위와 적용 상태

기존 조회 PR #6 위에 통합 표·필터·인원 집계·기간/가격/수강생 준비 구조를 추가합니다.
실제 Cloud Run/Neon/홈페이지/IAM, 회원·주문·결제 데이터 변경 없음. 기본 OFF. 새 DDL은 CI 전용 임시 DB에서만 검증합니다.
등록·수정·연장·수강 확정 API, 데이터 가져오기, 실제 결제/환불/영수증 발급은 제공하지 않습니다.
`confirmed`는 미래의 승인된 수강 확정 흐름으로 기록해야 합니다. 이번에는 합성 테스트가 직접 기록합니다.

## 계산과 아직 확정되지 않은 경계

준비 화면에서는 시작일을 포함하고, 시작일 + 누적 개월의 같은 날짜를 **독점 종료 경계**로 사용합니다.
표에는 그 하루 전을 마지막 수강일로 표시합니다.
예: 2026-10-01 시작 → 1개월 2026-10-31 / 3개월 2026-12-31 / 12개월 2027-09-30.
1개월 후 3개월 연장 → 누적 4개월, 마지막 수강일 2027-01-31.
계산은 최초 수업 시작일 + 총 개월 수로 한 번에 하므로 중간 2월 보정으로 날짜가 밀리지 않습니다.
남은 기간은 한국시간 기준 남은 사용 가능 날짜 수(마지막 날=1일). 시작 전에는 표에서 남은 기간 대신 — 표시.

**공개 전 확인 사항**: 29~31일 시작 후 다음 대상 월에 같은 날짜가 없는 경우.
PostgreSQL은 기본적으로 말일 보정하지만, 사업 규칙 승인이 없으므로 이를 자동 채택하지 않습니다.
이 경우 `calendar_review_required=true`, 종료일 NULL, `기간 확인 필요`이며 수강 중 인원 집계에서 제외합니다.
100년 초과 누적 기간도 데이터 검토 대상으로 중단합니다.
종료 후 재가입, 중도 합류, 휴강·일시정지, 무료 기간 연장, 부분 환불은 이번 확정 범위가 아니며 별도 설계합니다.

## 데이터 구조

- course_schedules: 기존 course_id(과정·기수 단위)의 공통 수업 시작일. 개인 시작일과 복합 FK로 일치 강제.
- course_monthly_prices: 1/3/12개월별 정상가/할인 판매가. 기본 비활성, 실제 값 없음. 기존 POST /orders 가격 로직은 변경하지 않음.
- learner_profiles: 회원 또는 별도 확인된 비회원 수강생. 내부 learner_id 기준, 이름·번호·메일이 같아도 자동 병합하지 않음.
- course_enrollments: 수강생×과정별 한 행. 기존 orders를 가입/수강 확정으로 변환하지 않음.
- enrollment_terms: 신청·연장 이력. 확정된 기간만 합산; 대기/취소는 기간에 포함하지 않음. 신청 당시 금액 스냅샷 보존.
- enrollment_read_model: 기간/최근 이용권/인원 집계용 읽기 뷰. 연락처는 마스킹.

같은 사람의 여러 과정은 전체 현재 인원에서 learner_id로 중복 제거하고, 각 과정 인원에는 각각 포함합니다.
계정 또는 비회원 확인을 거쳐 같은 learner_id로 연결되지 않은 레코드를 이름·전화번호로 추정 병합하지 않습니다.
같은 과정에 중복 수강 행은 UNIQUE로 막고, 연장은 term에 추가합니다.

## 표시값과 금전 정보

한 줄: 이름/닉네임/과정/기수/최근 신청 개월/누적 개월/수업 시작일/종료일/남은 기간/수강상태/
최근 신청금액/할인금액/실제 결제금액/전화번호/이메일/현금영수증 요청/발급 상태/신청일/회원가입일/이용권 수.
열 표시·숨김과 이름 열 고정 제공. 임의 사용자 정의 DB 열·저장 필터·열 순서 저장·엑셀 내보내기는 이번에 없음.
회원가입일은 연결된 members.created_at이며 비회원은 —. 신청일·결제일로 대신하지 않습니다.
최근 신청 기간은 마지막 미취소 term, 누적 기간은 확정 term 합계. 대기 연장이 있으면 이 둘은 다를 수 있습니다.
**신청금액은 결제 사실이 아닙니다.** PG 미연동이므로 실제 결제금액은 NULL/확인 전, 결제 상태는 not_connected.
현금영수증 요청은 true/false/미확인, 실제 발급은 unverified. 요청을 발급 완료로 표시하지 않습니다.
이 준비 테이블은 결제 원장이 아닙니다. 결제 연동 단계에서 검증된 orders/payment 원장과 연결해야 합니다.

## API와 권한

- GET /portal/api/admin/enrollments: 관리자만. 목록+필터와 동일한 전체 요약+과정별 인원.
- GET /portal/api/me/enrollments: 본인 세션의 member_id로만 제한. 요청에 member_id 추가하면 422.
- GET /portal/admin/enrollments: 새 통합 조회 화면. HTML에 개인정보 내장 없음.

필터: 이름/닉네임 부분 검색, 이메일/전화번호 전체 일치, 과정/기수/최근 1·3·12개월/수강상태/종료일 범위/영수증 요청.
정렬: 종료일/신청일/이름. 목록 최대 50행, offset 최대 10000. 집계는 현재 페이지가 아닌 필터 일치 전체입니다.
과정별 요약은 최대 100개이며 잘림 여부를 명시합니다. 같은 SQL 필터와 repeatable-read 스냅샷으로 집계/행 일치.
값은 SQL 바인딩, 정렬 식별자는 허용목록. 오류 본문에 사용자 검색어/연결 정보/예외 원문을 반환하지 않음.
조회 본체는 읽기 전용; 기존 로그인 세션 touch는 이전과 동일합니다. 최소권한 DB 계정과 조회 감사 이력은 공개 전 준비.
GET 검색어의 개인정보가 인프라 URL 로그에 남지 않도록 로그 보호도 공개 전 별도 확인해야 합니다.
원문 연락처 조회/다운로드는 아직 권한·감사 설계를 붙이지 않았으므로 제공하지 않습니다.

## 기능 플래그와 후속 단계

`RICHON_ENROLLMENTS_ENABLED=true`는 포털·인증이 먼저 정상 설정됐을 때만 허용됩니다.
`004_enrollment_read_models.sql`은 001/002/003 체크섬을 확인하는 명시적 적용기에만 연결합니다.
새 migration/적용기/테스트/문서는 런타임 이미지에서 제외됩니다. 실제 Neon에는 적용하지 않았습니다.
새 화면의 기존 관리자 메뉴 연결, 등록/연장/가격 편집, 실제 수강생 데이터 이전, 소셜 로그인과 관리자 지정은 후속 승인 범위입니다.
