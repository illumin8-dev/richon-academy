## 기술적 확인 / 남은 문제

| 분야 | 소스에서 확인한 사실 | 판정 |
|---|---|---|
| OAuth 식별 | 제공자·앱·subject로 식별, 이름·메일·전화로 자동 통합하지 않음 | 유지 |
| 인증 | 고정 HTTPS callback, state와 브라우저 결합, 소모·만료 검사, 카카오 app/subject 검증 | 구현됨 / 실제 인증은 별도 |
| CSRF | 실제 Origin과 폼 proof 검사, login/signup GET HTML same-origin 정책 | 구현됨 / 운영 재시험 필요 |
| 세션 | 토큰 해시, Secure/HttpOnly/host-only 쿠키, DB 현재 역할·상태 확인 | 구현됨 / 종단간 검증 아님 |
| 비밀번호 | 리치온 전용 비밀번호를 요구하지 않음 | Naver 검수 기준과 일치 |
| 소셜 정보 수집 | UID와 닉네임 사용. 닉네임 누락 시 기본 표시명. 실명·전화·메일을 고객정보에 저장하는 소셜 어댑터는 없음 | 동의항목/문서 정합성 필요 |
| 복귀 | 정확한 내부 경로만 허용 / 외부 URL·쿼리·인증 경로 차단 | 코드 있음 / 008 운영 미적용 |
| 회원탈퇴 | 로컬 탈퇴·파기·제공자 unlink/revoke 처리 없음 | 공개 전 작업 |
| 외부 연결 해제 | 카카오 unlink/account-state webhook 처리 없음 | 공개 전 작업 |
| 보유·파기 | state/ticket/session의 논리적 만료는 있음. 정기 물리 삭제 작업은 확인되지 않음 | 보유 정책과 실행 작업 필요 |
| DB·서버 | PR #14 소스 병합됨. 008 운영 적용·신규 backend 배포 완료 증거 없음 | 완료 표시 금지 |
| 자동배포 | `.github/portal/common.py` IAM-private 전용 / Naver env·secret 허용 목록 미포함 | 공개+edge gate 상태에 맞춘 별도 검증 변경 필요 |
| 배포 브랜치 | 조회한 배포 branch의 protected:false | 실제 WIF 신뢰 코드이므로 보호 규칙 검토 필요 |

Naver 연결은 `NAVER_CLIENT_ID` → `richon-naver-client-id:<활성 숫자 버전>`, `NAVER_CLIENT_SECRET` → `richon-naver-client-secret:<활성 숫자 버전>`이다. 런타임 계정의 각 secret 접근 권한도 검증해야 한다. 이 PR은 바인딩이나 IAM을 변경하지 않는다. `Settings.from_env`는 키가 둘 다 없으면 버튼을 숨기고 일부만 있으면 설정 오류로 거부한다.

탈퇴는 단순 행 DELETE가 아니다. 재인증, 모든 세션 취소, 제공자 연결 해제 실패 시 재시도/일관성, 수강·환불 기록의 법정 보존 분리, 외부 webhook 인증·멱등성 처리가 필요하다. OAuth callback과 webhook은 다르다. webhook 수신을 위해 전체 Access 보호를 해제하지 않는다. 별도 설계 승인 후 구현한다.

## 검수 판단

- Naver 일반 이용자 공개에는 사전 검수가 필요하다. 앱 등록자/관리자·테스터는 검수 전 시험 가능하다.
- UID 외 선택한 scope는 선택 동의 항목도 실제 활용 사례가 필요하며 단순 저장·통계만으로 충분하지 않다. 사용하는 닉네임과 아직 수집하지 않는 이름/메일/휴대전화를 구분한다.
- 앱 이름/로고는 리치온 브랜드, URL·Callback 일치, 독자 비밀번호 미요구를 확인한다.
- 버튼 → 제공자 동의 → 리치온 가입 동의 → 완료의 전체 동선과 정보 활용처를 캡처한다. Kakao 추가 동의항목 신청에는 로그인·탈퇴 동선도 증빙한다. 개인정보·코드·토큰은 캡처에서 제거한다.
- owner-only Access는 검수자 접근을 막을 수 있다. 무작정 해제하지 않고 자료 제출 또는 제한된 검수 접근을 먼저 결정한다. Naver 공식 문서는 구현 전 화면 기획서 제출도 허용한다.
- 교육/강의 서비스의 업종별 증빙과 신고 여부는 별도 확인이다. 로그인 승인 자체가 교육업 법적 요건 충족을 뜻하지 않는다.

수집·이용 동의는 방침 전체에 동의 하나 받는 것으로 끝내지 않는다. 목적, 항목, 기간, 거부권/불이익을 가입 화면과 연결 문서에서 명확히 알리고 선택 정보·광고 수신은 구분한다. `internal-test-v1`은 정식 운영 문서 승인 버전이 아니다.

저장소의 현재 구성상 Cloud Run/Neon은 싱가포르 리전이므로 국외 처리 검토가 필요하다. 오늘 실제 클라우드 리전을 조회한 것은 아니다. Cloudflare 국가·로그/백업·계약 법인까지 모두 싱가포르라고 단정하지 않는다. 개인정보 보호법 제28조의8의 적용 근거(별도 동의 또는 계약 이행에 필요한 위탁·보관 및 고지 등)와 Kakao가 별도로 요구하는 국외이전 안내/동의 설정을 함께 맞춘다. Kakao 콘솔의 개인정보 국외이전 설정 상태도 확인해야 한다.
